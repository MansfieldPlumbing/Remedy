# Remedy Build Documentation

This document describes the canonical local build system for the Remedy project.

## Prerequisites & Project Language Standard

- **C++ Standard**: **C++17** (`CMAKE_CXX_STANDARD 17`).
- **MSVC**: Visual Studio C++ Compiler supporting C++17 (`cl.exe`).
- **CMake**: Version 3.20 or later (`cmake.exe`).
- **CTest**: Test driver bundled with CMake (`ctest.exe`).
- **PowerShell**: PowerShell 5.1 or PowerShell Core.

## Toolchain & Checkout-Relative Environment

All repository-internal include and build paths are derived dynamically relative to the checkout root (`$PSScriptRoot` in `build.ps1`).

Toolchain discovery paths (MSVC compiler binaries, Windows SDK, CMake, and dotnet) are configured **process-locally** within `build.ps1` for the duration of the PowerShell build process and its child commands:
1. `build.ps1` prefers tools already present in the process `PATH`.
2. Documented `S:\bin` toolchain directories are used as process-local fallbacks when present.
3. No persistent environment mutation (User or Machine `PATH` modification) is part of the build procedure.

### Static MSVC C Runtime Selection

Native C++ targets in Remedy configure CMake policy `CMP0091` to `NEW` and explicitly set `CMAKE_MSVC_RUNTIME_LIBRARY`:

```cmake
cmake_policy(SET CMP0091 NEW)
set(CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>")
```

This ensures native executables link statically against the MSVC C runtime library:
- **Debug**: `/MTd`
- **Release / RelWithDebInfo / MinSizeRel**: `/MT`

### Scoped Dependency Verification

For the currently admitted native targets (`remedy_echo_worker` and `test_codec_golden`), static MSVC CRT linkage eliminates external debug runtime DLL dependencies (`MSVCP140D.dll`, `VCRUNTIME140D.dll`, `VCRUNTIME140_1D.dll`, `ucrtbased.dll`).

For these currently admitted native echo-worker and codec-test targets, built executables depend only on standard OS system libraries (`KERNEL32.dll`). Deferred components and future executable targets have not yet been dependency-audited.

## Generated Output Directory

All build artifacts generated by CMake, MSBuild/NMake, and test runs are placed strictly under the checkout-relative build directory:

```text
build/
```

## Canonical Local Build Command

To perform a clean build and run all active native tests, execute the canonical driver command:

```powershell
.\build.ps1 -Clean -Test
```

### Options

- `-Clean`: Removes the checkout-relative `build` directory before configuring and building.
- `-Test`: Executes active native tests via CTest after compilation.

## Fail-Fast Principles

`build.ps1` operates as a strict fail-fast driver:
- Every external command (`cmake`, `ctest`) is followed immediately by inspecting `$LASTEXITCODE`.
- If configure or build fails, execution halts immediately with a non-zero exit code.
- CTest is never invoked following a failed build step.
