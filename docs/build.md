# Remedy Build Documentation

This document describes the canonical local build system for the Remedy project.

## Prerequisites

- **MSVC**: Visual Studio C++ Compiler supporting C++20 (`cl.exe`).
- **CMake**: Version 3.20 or later (`cmake.exe`).
- **CTest**: Test driver bundled with CMake (`ctest.exe`).
- **PowerShell**: PowerShell 5.1 or PowerShell Core.

## Toolchain & Process-Local Environment

Toolchain discovery paths (MSVC compiler binaries, Windows SDK, CMake, and dotnet) are configured **process-locally** within `build.ps1` for the duration of the PowerShell build process and its child commands.

### Static MSVC C Runtime Selection

Native C++ targets in Remedy configure CMake policy `CMP0091` to `NEW` and explicitly set `CMAKE_MSVC_RUNTIME_LIBRARY`:

```cmake
cmake_policy(SET CMP0091 NEW)
set(CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>")
```

This ensures native executables link statically against the MSVC C runtime library:
- **Debug**: `/MTd`
- **Release / RelWithDebInfo / MinSizeRel**: `/MT`

### Removal of Persistent Environment Dependencies

The initial build setup used a persistent User PATH modification adding MSVC Debug CRT directories (e.g. `debug_nonredist`) to resolve missing dynamic runtime DLLs (`MSVCP140D.dll`, `VCRUNTIME140D.dll`, `VCRUNTIME140_1D.dll`, `ucrtbased.dll`).

While that workaround allowed dynamically linked Debug executables (`/MDd`) to load, the canonical build replaces dynamic linking with static CRT linkage (`/MTd` / `/MT`). Consequently:
- Debug CRT DLL directories are **not** required in system or user PATH.
- No persistent environment mutation (User or Machine PATH modification) is part of the build procedure.
- Built executables depend only on standard OS system libraries (`KERNEL32.dll`).

## Generated Output Directory

All build artifacts generated by CMake, MSBuild/NMake, and test runs are placed strictly under:

```text
S:\Remedy\build
```

## Canonical Local Build Command

To perform a clean build and run all active native tests, execute the canonical driver command:

```powershell
.\build.ps1 -Clean -Test
```

### Options

- `-Clean`: Removes the `S:\Remedy\build` directory before configuring and building.
- `-Test`: Executes active native tests via CTest after compilation.

## Fail-Fast Principles

`build.ps1` operates as a strict fail-fast driver:
- Every external command (`cmake`, `ctest`) is followed immediately by inspecting `$LASTEXITCODE`.
- If configure or build fails, execution halts immediately with a non-zero exit code.
- CTest is never invoked following a failed build step.
